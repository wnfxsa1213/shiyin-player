状态：用户已整体同意页面与默认规则，首版已在 `codex/ui-interaction` 实现。场景、素材与播放接口已接入正式播放器；功能与开发机验证见 [验收记录](visual-scenes-validation.md)。普通集显、8GB、60Hz 设备的性能验收仍待实机完成。

## 产品范围

- 主界面采用轻量表现，沉浸界面采用完整表现，两者沿用同一套场景内容。
- 背景支持本地 JPEG/PNG/WebP 图片、渐变与当前歌曲封面。
- 场景由背景、粒子特效、配色与强度组成，是保存和轮换的基本单位。
- 以预设选择为主，保留背景选择、音乐跟随开关与自己的搭配保存；首版不做完整粒子参数编辑器。
- 默认强音乐跟随，要求明显响应音乐强弱与低频变化。用户已确认“明显即可”，不要求精准 BPM 或逐鼓点同步。
- 自动调整视觉质量，优先保证交互响应。基础验收设备档为普通集显笔记本、8GB 内存、60Hz；实际基准机器和达标数据尚待落实。
- Radio session 和 Lyrics read-model 两项架构开发继续暂停。

## 页面与操作

“视觉场景”作为独立入口，播放区保留打开场景库的快捷入口。主内容左侧显示预设画廊，右侧显示候选场景预览和基础选项；底部集中展示轮换状态、锁定与“换一个”。较窄展示环境下改为上下布局。

| 操作 | 明确行为 |
| --- | --- |
| 点击场景卡片 | 更新预览，不改变当前已应用的场景 |
| 选择背景 | 可以选场景原配、当前专辑封面或自己的图片；先在预览区展示 |
| 应用场景 | 将候选搭配应用到播放器，并记住当前搭配；背景或跟随设置变动也属于待应用变更 |
| 另存搭配 | 在场景库中保存独立条目；保存与是否加入轮换分别控制 |
| 加入我的轮换 | 将所选场景加入轮换集合；轮换集合与音乐播放队列独立 |
| 锁定当前场景 | 暂停自动轮换，手动选择和“换一个”仍可用；手动换到新场景后仍保持锁定 |
| 换一个 | 从轮换集合中手动随机选下一套，不重复当前场景；只有一套时说明无需切换 |
| 沉浸预览 | 查看候选场景在大面积背景和歌词布局中的表现，退出后回到原选择位置 |

候选搭配与已应用搭配分开保存，应用按钮应真实反映背景、配色、音乐跟随等是否已生效。预览期间暂缓自动场景切换。临时应用的搭配不会自动加入轮换集合，另存后可自行加入。

交互草图用于评审布局和操作。粒子律动使用演示信号，保存仅在预览会话内有效；它不能证明正式播放器的音画同步、素材持久化或资源占用。

## 自适应随机轮换的默认规则

用户用“随机应变”委托系统根据上下文安排轮换，具体化为以下默认策略：

1. **随机顺序**：只使用加入轮换集合的场景，以随机洗牌的方式尽量覆盖全部场景后再重复；新一轮避免首先重复当前场景。
2. **随曲机会**：新歌曲或单曲循环的新一轮播放真正开始时，可以切换；同曲故障重试、暂停恢复和缓冲恢复不触发。
3. **最短驻留**：两次自动切换至少间隔 60 秒有效播放时间，连续快速切歌时保持场景稳定。
4. **长曲补充**：同一场景持续有效播放 5 分钟仍未切换时，安排一次随机轮换。
5. **操作避让**：用户在预览/搭配场景、拖动进度或操作菜单时暂缓；最近 3 秒有交互时也延后，空闲后最多执行一次待处理切换。
6. **暂停与隐藏**：未播放、加载、暂停、缓冲、窗口不可见时停止自动轮换和不必要的视觉更新。这些时段不累计有效播放时间；恢复可见后不补跑隐藏期间错过的轮换。
7. **锁定优先**：锁定状态取消待处理自动切换。解除锁定后重新计算自动切换时机，避免立即突变。
8. **过渡与失败**：新场景资源就绪后，以约 400ms 淡入过渡；失败时保留当前场景并提示。减少动态效果偏好下使用静态、无连续粒子的呈现。

60 秒、5 分钟、3 秒和 400ms 是这份方案提出的默认值，后续可以依据可用性验证调整。它们不会进入领域词汇表，也不改变音乐本身的播放或切歌规则。

## 首批预设

每一项都应有明显的运动与形态差异，配色变体不计为新的粒子类型。

| 场景 | 粒子特点 | 默认背景 |
| --- | --- | --- |
| 星海 | 多层星尘、疏密与亮度变化 | 深空渐变 |
| 雨夜 | 细长雨线、速度与雨量变化 | 暮紫渐变 |
| 初雪 | 不同大小的雪点、轻微横向漂移 | 冰蓝渐变 |
| 萤火 | 分散光点、亮度与运动变化 | 森林渐变 |
| 流星 | 稀疏拖尾与短时爆发 | 靛蓝渐变 |
| 气泡 | 轮廓气泡、上浮和大小变化 | 海蓝渐变 |
| 花信 | 有方向和旋转的花瓣 | 玫瑰渐变 |
| 共振 | 音乐强弱驱动的径向粒子爆发 | 琥珀渐变 |

每套预设均允许换用自己的背景。预设画廊使用静态缩略图，只有选中预览与当前实际使用的效果需要运行；预览和过渡的额外开销也必须测试。

## 素材与视觉运行规则

- 本地图片导入到应用管理的素材库，以避免原文件移动后失效；生成显示资源和缩略图，原始用户文件保持独立。
- 背景素材复用并去重，场景引用素材。导入体积、尺寸和缓存上限通过目标环境基线测量后明确，不能默认无限预载。
- 图片加载失败时回退到场景自带渐变；文字、歌词和操作控件保持可读。
- 场景库选择、预览草稿、当前应用场景和轮换集合有明确区分，避免浏览预设时污染实际设置。
- 视觉模块消费播放事实，不决定播放重试、队列推进或音频加载。
- 现有 currentTrack、playbackId 与 playing 状态都不能单独识别新一轮播放开始；实现时复用生命周期内部的逻辑播放身份，提供去重后的可消费信号。
- 音乐驱动复用现有频段强弱基础，并验证事件关联、时序平滑与暂停清理。强跟随主要影响粒子与频谱，文字和控件位置稳定。
- 自动质量调整以减少粒子数量、绘制分辨率和背景绘制频率为手段；采用稳定的观察窗口与恢复条件，避免质量来回跳变。主界面表现仍低于沉浸界面。
- 已对照 tsParticles slim 与 Canvas；首版采用 Canvas2D 和八种效果绘制器，共用调度、质量控制与频谱平滑。选择原因见 [ADR 0002](../adr/0002-scene-renderer.md)。

## 实现边界

- `frontend/src/lib/scenes/model.ts` 定义预设与持久化 schema；`sceneStore.ts` 分离草稿、当前搭配、自定义库和轮换集合。设置使用 `visualScenes.v1`，写入串行化；最新应用请求优先，资源未就绪不提交。首版基础强度由预设确定，音乐跟随为明显强度响应，主界面与沉浸界面的表现强度由渲染上下文确定。
- `rotation.ts` 通过可注入时钟与播放事实执行默认规则；`runtime.ts` 在应用层启动一个调度器，汇总原生窗口、页面可见性与交互避让。预览页、表单焦点、拖动和菜单阻止自动提交；加载期间的新交互和锁定仍可取消待应用的自动切换。
- 播放生命周期公开 `listening`，首次实际 Playing 才给出 `sessionId`。重试保留身份，单曲循环重建；加载意图与真正接管的曲目分别表示。频谱带 `playbackId` 与播放器采集时的 `emittedAtMs`，过期或无关事件丢弃；暂停、加载、缓冲、隐藏及尝试变更清理共享频谱。音频强度按快速上升、缓慢回落平滑，过时信号归零。
- `renderer.ts` 承担八种效果、粒子分配、光点缓存、分辨率与绘制频率。画廊使用静态 SVG；主界面、预览和沉浸界面共享一个 Surface 实现，覆盖区域停止连续绘制。每次退出解除 RAF、观察器与画布资源；未完成的图片请求按使用者计数共享，离开预览时取消无人使用的加载。
- 自动质量从中档开始，基础粒子上限为 40 / 80 / 128，绘制分辨率为 50% / 75% / 100%，总像素不超过 160 万，背景绘制上限为 20 / 30 / 30fps；主界面进一步减少数量与分辨率。两个持续不良的 2 秒窗口降档，16 秒持续良好后升档。以上为当前工程预算，不是低配机器的达标承诺。
- Rust 的 `SceneAssets` 在应用数据目录 `scene-assets` 管理原始副本、显示图、缩略图和元数据。按 SHA-256 去重，解码前限制 20 MiB / 2400 万像素，解码分配预算 128 MiB；处理 EXIF 朝向，显示图长边最多 2560，缩略图最多 320，不放大小图片，派生资源统一静态 WebP。素材库限制 512 MiB，页面可移除未引用素材；耗时工作离开 UI 线程。
- 原始二进制 IPC 避免把文件展开为 JSON 数字数组。`scene` 异步图片协议只接受哈希文件名的显示图和缩略图；CSP 显式允许该协议。失败应用保留原场景，已存素材损坏或丢失时显示渐变并提示。
- 新场景背景准备好后进行 400ms 过渡；前景文字和控件位置稳定。减少动态效果时停止连续粒子与过渡。底栏、侧栏与队列使用实色背景；进度条仅在可见播放时插值，隐藏沉浸控件不可聚焦。

## 验收与实施顺序

1. **比较效果与基线**：在相同画布尺寸、粒子数量和帧率下测试现有绘制基础与候选库；记录交互反馈、帧时长、CPU、内存、GPU，以及暂停/恢复与多次场景切换。
2. **场景基础与背景导入**：实现素材管理、场景预设、预览/应用/保存和当前搭配恢复，先用少量代表效果贯通路径。
3. **随机轮换与音乐跟随**：实现去重的播放开始信号、自适应轮换、音乐驱动和视觉暂停策略。
4. **完整首批预设与 UI 打磨**：接齐八类效果，验证主界面与沉浸界面，修整播放栏、队列和键盘交互的一致性。

功能验收覆盖：预览不误应用、背景变动正确标记、保存与加入轮换独立、随机不立即重复、快速切歌与重试不反复切场景、长曲轮换、锁定/解锁、隐藏/恢复、图片丢失回退、强跟随与音频暂停、反复导入与切换后的资源回收。

性能设计目标为普通可见操作反馈约 100ms 内、60Hz 基准下界面滚动/拖动稳定 60fps、背景效果默认 30fps 并自动调整。CPU/内存/GPU 的数值上限需要先测量后冻结；当前没有性能达标结论。Chrome 中的交互草图验证不替代 Tauri/WebKitGTK 的正式验收。

正式实现继续运行现有播放与推荐回归，并增加场景状态、调度与资源生命周期的必要测试。
