# 首页、导航与搜索反馈

状态：已实现并通过功能与浏览器验收，位于 `codex/home-navigation-search`，待分支评审与合并。基于 `v0.2.0`，沿用现有播放生命周期、歌单与智能推荐接口。见 [验证记录](home-navigation-search-validation.md)。

## 页面方案与操作

首页从上到下为简短问候、四个紧凑入口、继续收听、我的歌单、智能推荐。默认窗口 1200×800、最小窗口 900×600；页面纵向滚动，底部播放栏始终可达。

| 入口 | 操作与结果 |
| --- | --- |
| 搜索音乐 | 进入搜索页；输入关键词后搜索，Enter 立即提交 |
| 我的歌单 | 滚动并将焦点移到首页歌单标题；展示用户歌单集合，点击具体歌单才打开详情 |
| 智能推荐 | 进入现有 `/daily` 页；首页预览读取同一智能推荐数据，歌单不充当推荐内容 |
| 播放详情 | 打开现有沉浸播放界面，保留当前播放状态和队列；首页、侧栏及底栏名称一致 |
| 继续收听的歌曲 | 播放该单曲并保留队列；明确歌曲名、歌手与音源 |
| 歌单卡片 | 打开歌单详情，封面提示为进入详情，避免播放图标暗示立即播放 |

侧栏 `/daily` 与目标页统一使用“智能推荐”。“电台”和“沉浸 FM”入口改为“播放详情”；本轮不新增开始电台的动作。Radio session 与 Lyrics read-model 继续暂停。

## 首页状态

- 继续收听为空：说明暂无播放记录，提供搜索入口。
- 歌单：加载、未登录、已登录但为空、获取失败分别表达；失败可重试，保留已有歌单并标注刷新失败。默认展示前六个，可展开其余歌单。
- 智能推荐：仅使用真实推荐结果；复用现有 store 的加载与缓存，提供查看更多、刷新与失败重试。音源降级展示可用音源；仅有重温经典时明确标注；未登录时给出设置入口。
- 登录状态检查失败时提供重试，不推断为未登录。检查及推荐失败不会自动循环请求。

## 搜索状态与请求规则

| 状态 | 内容与操作 |
| --- | --- |
| 输入前 | 搜索提示；纯空白视为空输入 |
| 等待输入完成 | 450ms 防抖；显示准备搜索的关键词与音源；中文输入法组合期间不发请求 |
| 加载 | 持续显示正在搜索的关键词和音源；首次显示骨架，有历史成功结果则保留 |
| 成功 | 标明实际关键词、音源及本次返回数量；歌曲沿用现有播放与菜单操作 |
| 无结果 | 仅在请求成功且返回空数组时显示；给出换词或切换音源提示 |
| 失败 | 常驻错误说明和重试按钮；重试当前失败的关键词与音源，不显示为无结果 |
| 旧结果 | 新请求等待、加载或失败时，明确显示“上次结果”及它自己的关键词、音源；结果仍可播放 |

输入、切换音源、清空与卸载立即使旧请求失效；旧成功与旧失败都不能覆盖新状态。音源切换、Enter 与重试立即请求，原防抖计时取消。清空立即恢复输入前状态并清除旧结果。多个页面实例不共享请求序号。

搜索控件置于 form；音源标签支持方向键与 Home/End，结果列表保留键盘播放和菜单行为。状态用独立的 live region 播报，整个歌曲列表不作为 live region 重复朗读。新结果重置列表位置，保留旧结果时不重置其滚动。

超长关键词以省略号显示，悬停可查看完整内容；音源、数量与失败原因保持可见，避免长文本挤走重试按钮和结果列表。请求失效只阻止旧响应写回 UI，不取消已经发给后端的工作。

- 前端全部回归和生产构建；保留播放、推荐、视觉场景回归。
- Chromium 与 Linux WebKitGTK：1200×800、900×600，深浅主题，长文字、滚动、鼠标/键盘、空状态及失败恢复；用隔离 IPC 固定输入，不依赖真实音乐账号。
- 记录截图及检查结果。本轮属于功能和界面验收，不追加已暂停的压力测试。
