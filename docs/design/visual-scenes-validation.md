原生检查使用独立 `XDG_DATA_HOME` / `XDG_CACHE_HOME`，没有修改日常使用的设置或背景。原生窗口恢复时，当前 GNOME 测试会话中的 `unminimize` 单独调用未能可靠激活窗口；复测按进程标识定位测试窗口，经 GDK 显示、置前并激活，确认真实窗口状态、应用可见性与绘制一同恢复。该辅助只存在于本地验证脚本。

频谱关联检查通过真实 Tauri event 通道发送测试载荷，验证旧播放尝试、过期事件被丢弃，当前信号被接收，暂停时清零。自动化播放画面使用测试曲目信息和合成频谱，未播放在线账号曲目。GStreamer 实际管线仍由既有本地 WAV / fakesink 回归覆盖。

## 渲染选型对照

环境：Ubuntu 24.04、WebKitGTK 2.52.6、GStreamer 1.24.2；开发机为 Core Ultra 9 275HX、约 32GB 内存，可见 Intel 集显与 NVIDIA RTX 5070 Laptop。WebKit 加速策略设为 Always，但没有确认实际采用的 GPU，也没有 GPU 使用率、显存或功耗数据。

Canvas2D 与 tsParticles slim 4.4.0 在同一 1000×600 画布中绘制移动圆点，目标 30fps、关闭 HiDPI 放大；每阶段预热 1.5 秒、采样 5 秒。第二次交换执行顺序。CPU 来自独立 GTK/WebKit 进程树，以占用一个逻辑核的百分比表示。

| 圆点数 | Canvas 回调 P95 | tsParticles 回调 P95 | Canvas CPU | tsParticles CPU |
| --- | --- | --- | --- | --- |
| 200 | 1ms | 1–2ms | 12.2–12.8% | 19.6–20.2% |
| 1200 | 4ms | 7ms | 18.3% | 26.3–26.6% |

这里的回调时间是包裹 RAF 回调测得的 JavaScript 执行时间，包含测试探针，不能替代 GPU 绘制耗时。计时粒度约 1ms。进程 RSS 包括 GTK、WebKit 及缓存，求和还可能重复计算共享页；同一页面同时加载候选库，无法据此精确分离两者内存成本。结果支持当前八种预设采用较小的 Canvas 实现，不代表通用效果库在所有场景中更慢。

## 正式渲染路径测量

以生产模式打包真实 React 前端，放入独立 WebKitGTK 窗口。音源和设置 IPC 使用测试替身，因此以下 CPU/RSS 不包括 Rust 播放器、音频解码与实际音源请求。

1000×650 窗口中逐一运行八套场景，每套预热 1 秒并采样 3 秒，初始自动质量为中档。全部场景都有有效绘制，结果如下：

- RAF 间隔 P95 为 18–19ms，包裹的 JavaScript 回调 P95 为 0–1ms；报告中的 0 表示低于本次计时分辨率。
- 每个 3 秒窗口记录 82–85 次场景绘制，约 27–28fps。代码上限为 30fps，这次实测没有证明稳定达到 30fps，也没有证明整套 UI 稳定 60fps。
- 自动点击轮换控件至下一次 RAF 回调为 2–3ms。这是局部反馈观测，未测量从输入到最终屏幕呈现的完整延迟。
- 进程树 CPU 为单个逻辑核的约 47–61%，RSS 求和峰值约 467 MiB。额外连续切换 32 次后，短时停止阶段的 RSS 约 463 MiB；CPU 约 15%，运行中的场景画布为 0。

短时重复切换未显示持续攀升的趋势，但不能凭此证明长期无泄漏。RSS 与 CPU 数据用于开发机上的比较，尚未冻结为产品资源上限。

高分辨率强信号检查另以 1920×1080、星海/萤火/花信、全幅合成频谱进行，给自动质量足够预热时间。测试窗口取消接收桌面键盘焦点以保持采样状态。该检查发现原先大于 40ms 的慢帧阈值会放过约 33ms 的帧间隔，现已改为大于 26ms 即计入慢帧窗口；回归覆盖这种压力下的降档与恢复迟滞。开发服务器期间或窗口状态变化导致的空采样未用于性能结论。

最终压力采样中，三种效果都自动降至低档，3 秒内分别绘制 54、56、55 次；回调 P95 约 1ms，操作至下一 RAF 回调为 2–4ms，停止后连续绘制为 0。进程树 CPU 为单核约 74–76%，RSS 求和峰值约 476 MiB。这组无焦点窗口的 RAF 间隔 P95 仍为 34–42ms，因此它验证了自动降档与资源回收，不能作为高分辨率下稳定 60fps 的结论。

## 重现与补充验收

```bash
cargo test --workspace --locked --offline
npm --prefix apps/rustplayer-tauri/frontend test
npm --prefix apps/rustplayer-tauri/frontend run build
```

`--offline` 适用于依赖已缓存的当前环境；新环境先安装依赖。测试入口为 `frontend/tests` 中的生命周期、场景、图片、运行时、进度与页面测试，以及 `scene_assets.rs` / `events.rs` 的 Rust 测试。

本次工作区的脚本、截图和原始采样保存在 `work/ui-scenes/benchmark`、`work/ui-scenes/product-qa`，不属于产品入口。独立测试页面在验证完成后从前端目录移出，生产应用没有测试路由、测试数据或额外窗口控制权限。

在普通集显、8GB、60Hz 实机验收时，应覆盖：真实音乐强弱变化；列表滚动与进度拖动；高分辨率自定义图片；自动降档与恢复；减少动态效果；多次最小化/恢复；长时间播放和场景轮换。需要补测 GPU、显存和能耗，并在这些条件下确定 CPU、内存及帧时长预算。本次结果不替代这些目标设备检查。
