# 播放生命周期

本轮对应架构方案 2，在 `codex/playback-lifecycle` 上收敛播放请求、后端事件、重试、自动切歌、播放行为与失败回滚。

## 职责与 interface

`createPlaybackLifecycle` 创建独立的播放器状态与动作。界面继续通过 `usePlayerStore` 读取状态和发出播放、暂停、跳转、切歌、清队列等意图。App 负责事件订阅，将事件交给生命周期 module，不再自行决定重试或切歌。

- Zustand 队列与状态是进程内依赖；状态、请求代次、重试次数与行为计时都属于同一个实例。
- Tauri/GStreamer 是自有的跨进程依赖，由生产 adapter 和测试内存 adapter 接入。
- 推荐批次沿用已有 interface；本轮只保证过期补曲不会污染已清空或替换的队列。私人 FM 与无限电台会话统一留在方案 3。
- 频谱继续走共享数组，不进入高频 React 状态更新。

## 播放规则

- 每次加载、重试、清空都有递增的播放请求标识。后端在解析流地址前登记请求，加载时再次检查；旧地址结果、旧事件和旧重试不能覆盖新播放。
- 加载已入队后的实际接管事件可能晚于新的选择。module 分别保留待播放意图与实际管线的收听状态，在新请求失败时恢复真实曲目，并在更高代次接管后丢弃旧记录。
- 自然结束由独立的结束事件表达。普通停止和出错后的停止不触发额外切歌。
- 同一次逻辑播放最多重试两次；重新进入 Playing 不重置预算。恢复位置随加载请求进入引擎，在新管线就绪后跳转，避免迟到的 seek 跳转下一首歌曲。
- 新曲目的流地址请求失败时，恢复仍在实际播放的上一首；已经进入新管线后的失败按该曲目的重试规则处理。
- 重试耗尽后，顺序和随机模式可跳过失败曲目；单曲循环、仅一首或本轮队列曲目均失败时停止，避免无限失败循环。
- 单曲循环重新加载当前曲目，不使用“seek 后 toggle”猜测引擎状态。
- 清空队列或删除最后一首同时停止引擎，取消旧请求和补曲。
- 播放行为只累计实际 Playing 的时长，暂停、加载和缓冲不计入；重复状态事件不重置计时。未实际播放的请求不产生行为记录，切歌、结束、清空、关闭只结算一次。
- 播放按钮、快捷键和进度拖动共用生命周期动作，失败统一提示。音量在新管线加载后仍保留。
- 暂停意图在加载和缓冲期间有效；若旧曲目仍在发声，也会立即请求暂停旧管线。播放按钮读取播放意图，进度插值和行为计时仍读取实际状态。

## 验证

通过 module 的 interface 验证快速切歌、旧请求失败、旧事件、初始失败回滚、两次重试、断点恢复、单曲循环、自然结束、清队列、补曲竞态、暂停/缓冲计时和幂等结算。后端验证请求代次、事件标识、真实 GStreamer 管线结束与控制行为；前端同时保留音乐发现回归测试。
