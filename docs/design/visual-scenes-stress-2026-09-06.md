# 当前电脑的视觉场景压力测试

测试日期：2026-09-06。播放器代码版本：`71319a1`，分支 `codex/ui-interaction`。

结论：本轮功能和资源回收检查通过；连续切换路径未观察到随轮次持续增长的内存。高分辨率场景仍有长帧，尚不能判定达到稳定 60fps。前台短对照也出现长帧，失焦不是唯一解释。

## 环境与方法

- Ubuntu 24.04 / X11 / GNOME，WebKitGTK 2.52.6。
- Core Ultra 9 275HX，24 个逻辑核；32GB 内存，系统报告约 30.8GiB。
- Intel Graphics 与 NVIDIA RTX 5070 Laptop GPU，NVIDIA 驱动 595.84。
- 当前显示模式为 2560×1600 / 240Hz 和 2560×1440 / 120Hz，未修改用户的显示器设置。测试窗口实际尺寸与 DPR 均单独记录。
- 使用 Rust release 构建和生产模式前端，资源从 Tauri 自定义协议加载。素材导入、设置保存及频谱 event 走真实原生路径；播放身份、歌词、队列及频谱为测试数据，未使用账号或产生声音。
- 单独创建 XDG 数据与缓存目录。约每秒采集所启动进程及子进程的 CPU、PSS、RSS、GPU 设备与可获取的 NVIDIA 指标。

完整运行约 **398 秒（6 分 38 秒）**，通过 **271 项检查**，前端异常为 **0**。覆盖三张 3840×2160 PNG、100 套保存搭配、5000 条队列滚动、八种效果充分预热、2560×1440 图片背景、三轮共 240 次应用切换、100 次预览选择，以及三次隐藏/恢复和最终停绘。

## 主要测量

CPU 的 100% 表示占用一个逻辑核，表内数值不是整机百分比。PSS 为进程树的比例分摊内存，避免直接相加 RSS 对共享页的重复计算。CPU/PSS 使用同一阶段内的采样间隔，排除跨阶段样本。

| 场景 | RAF 间隔 P95 | 场景绘制次数/秒 | CPU 均值 | PSS 均值 |
| --- | --- | --- | --- | --- |
| 1200×800，5000 条队列滚动 | 19ms | 20.7 | 77.9% | 256.5MiB |
| 1920×1080，八种粒子效果 | 34–37ms | 20.4–21.6 | 90.9–96.0% | 275.8–290.9MiB |
| 2560×1440，图片背景与萤火 | 56ms | 20.0 | 108.1% | 319.4MiB |
| 三轮各 80 次应用切换 | 63–65ms | 含静态重绘，不作稳定帧率解释 | 107.2–110.3% | 363.3–366.4MiB |
| 100 次候选预览切换 | 19ms | 含静态重绘，不作稳定帧率解释 | 67.8% | 381.7MiB |
| 最终暂停，15 秒观察 | 无连续应用 RAF | 0 | 11.8% | 382.4MiB |

八种效果在动态采样期间持续获得新鲜频谱，自动质量均降至低档。场景锁定控件的自动操作至下一 RAF 回调 P95 为 3–4ms。该数字是局部调度反馈，不是输入到屏幕呈现的完整延迟。

最重的连续切换段 RAF 最大间隔为 78ms；大图稳态段最大间隔为 75ms。持续切换本身包含图片就绪、背景过渡和设置写入，这些负载应保留在实际优化目标中。

## 内存与停止行为

三轮相同切换工作量后，各静置 10 秒，PSS 均值依次为 **353.8、352.9、353.4MiB**。这段路径没有显示随重复轮次持续增长的趋势。

全程采样 PSS 峰值约 **392.9MiB**，RSS 求和峰值约 **716.2MiB**。进入含 100 套搭配的图库后出现一次性增长，最终暂停 PSS 约 382.4MiB；这与重复切换的内存趋势分别记录，不能用初始空页面和最终已加载图库直接判断泄漏。

三轮静置、三次隐藏和最终暂停期间，连续画布绘制均为 **0**；恢复显示后重新开始绘制。此次约六分半的运行不等于长时间无泄漏证明。

## 素材与 GPU

三张 PNG 的原始尺寸均为 3840×2160，压缩后约 132–135KB；原生导入耗时为 **226–231ms**。重复导入返回同一素材标识。该结果覆盖大像素尺寸的派生图生成，不代表接近 20MiB 上限的高熵照片导入耗时。

观察到应用进程打开 `/dev/dri/renderD128` 与 NVIDIA 设备；sysfs 将该节点映射至 `0000:02:00.0` 的 RTX 5070。`nvidia-smi pmon` 能看到属于测试进程树的图形进程，但大多数样本的 SM 利用率不可用。可读取的 framebuffer 常见值约 7MiB、采样峰值约 12MiB，不能将其视为完整图形内存账目，也不能由此证明 Canvas2D 的全部工作都在 GPU 上完成。

WebGL 返回的 `Apple GPU` 字符串与本机设备不符，本报告弃用它作为硬件识别依据。整卡 GPU 利用率和功耗同时受桌面及其他程序影响，原始采样保留这些值，未全部归因于播放器。

## 前台对照与下一步

额外运行约 29 秒的短对照，在动态采样时维持测试窗口焦点。星海、萤火和大图阶段的焦点采样比例均为 100%；RAF 间隔 P95 分别为 **34、33、49ms**。该短对照通过 23 项检查；它与同样使用短预热的初始试跑相近，未显示仅恢复焦点就能消除长帧。

后续性能工作优先拆解高分辨率背景的绘制、合成和 WebKit 调度耗时。当前 JavaScript 绘制回调较短，不能据此认定整条呈现路径已经足够快。普通集显、8GB、60Hz 的验收仍需相应实机；本轮只对当前电脑和记录的场景负责。
