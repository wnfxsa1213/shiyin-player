# 首版场景采用 Canvas2D 共享渲染器

用户优先要求响应快、流畅、低资源，同时希望首批八类粒子有明显差异。我们对照了 Canvas2D 与 tsParticles slim 4.4.0：相同尺寸、移动圆点数量与目标帧率下，WebKitGTK 两次交换运行顺序的检查均显示 Canvas 的 JavaScript 回调时间和进程 CPU 开销较低。数据、方法和限制见 [验证记录](../design/visual-scenes-validation.md)。

首版采用 Canvas2D，每类效果提供绘制函数，统一处理粒子分配、时钟、音乐输入、可见性和自动质量调整。光点使用缓存图像，画廊使用静态缩略图。生产包无需引入 tsParticles；代价是八种效果的运动、资源释放和后续扩展由项目维护。

这项决定依据的是已选择的少量预设和当前 WebKit 测量，不代表 Canvas 对所有效果都更快。未来加入复杂连线、交互场景或更多第三方效果时，应在同一资源与交互预算下重新评估候选库；新效果继续通过场景与 Surface 边界接入。
