## 建议实施顺序

当前已实现可保存、可轮换的视觉场景与播放主流程 UI。后续建议从首页、导航与搜索反馈开始。

| 顺序 | 迭代 | 主要交付 |
| --- | --- | --- |
| 1 | 播放主流程 UI 与交互统一（已实现） | 播放栏的加载、缓冲和失败反馈；明确歌曲入口与队列操作；当前播放定位、空队列和键盘操作 |
| 2 | 首页、导航与搜索反馈 | 修正收藏、推荐、电台与沉浸入口的名称和去向；梳理首页信息层次；区分搜索加载、无结果、失败和旧结果，提供重试 |
| 3 | 沉浸界面与视觉一致性 | 打磨封面、歌词与控制区的层次和窗口适配；统一字体、间距、控件状态；保证不同背景下的可读性 |
| 4 | 场景库后续增强 | 根据前三轮的实际使用问题完善预设浏览、搭配管理与轮换反馈，再评估新增特效的优先级 |

### 本轮交付：播放主流程 UI 与交互统一

- **播放栏**：持续表达加载、缓冲、暂停和失败；切歌过程中明确目标歌曲与当前状态。恢复入口复用现有播放生命周期动作，所需状态由生命周期模块提供，界面不自行维护请求、重试或队列推进。
- **播放入口**：已形成歌曲行、推荐卡片和队列条目的操作对照表，将“播放这首”“下一首播放”“加入队列”“播放全部”分开表达；播放单曲保留队列，播放全部明确替换。具体单击、双击与键盘行为见页面方案。
- **队列面板**：突出当前播放项，提供定位当前歌曲的入口，明确移除和清空的结果，完善空状态、长列表滚动与焦点反馈。
- **交付与验收**：方案、状态清单、代码和截图已完成。覆盖快速连续切歌、加载时暂停、缓冲恢复、失败重试、移除当前项与清空队列；功能回归和生产构建通过，具体窗口与引擎覆盖范围见验证记录。

每轮先明确用户操作和界面状态，形成可查看的页面方案，再实现与验证。

Radio session 与 Lyrics read-model 继续暂停。普通集显笔记本 8GB、60Hz 仍是后续待实机验证的基础档；当前开发机结果不替代该档验收，高分辨率长帧也尚未解决。

## 体验验收

- 按应用当前的默认窗口 1200×800 和最小窗口 900×600 检查布局、滚动、长标题与控件可达性。
- 覆盖深色与浅色主题、鼠标与键盘操作。
- 检查未登录、空队列、播放中、暂停、加载、缓冲和失败恢复。
- 明确单击、双击、右键、Enter、空格和方向键的行为，避免一次操作同时触发多个播放动作。
- 弹层打开、关闭后焦点位置明确，隐藏内容不会抢走键盘操作。
- 验证减少动态效果设置、歌词可读性和状态反馈，保留现有播放与推荐回归测试。
