## 初步梳理

以下为当前代码中可见的行为与结构，尚未完成实际窗口的逐页视觉验收。

| 区域 | 当前情况 | 优化方向 |
| --- | --- | --- |
| 播放入口与队列 | 普通歌曲行双击播放并追加到队列；推荐卡片单击播放并替换队列；队列条目单击切歌 | 明确播放、下一首播放、加入队列、播放整个列表的行为，并让用户能预期队列变化 |
| 播放状态 | 底部播放按钮已经区分播放意图与实际状态，但加载、缓冲和失败缺少持续可见的状态表达 | 播放栏展示可理解的状态，错误提供明确恢复入口，按钮与提示保持一致 |
| 导航语义 | “电台”“沉浸 FM”“展开歌词”打开同一界面；首页“我的收藏”打开首个歌单，“为你推荐”显示已有歌单 | 名称与内容、操作相符，明确进入当前播放详情与开始电台的区别 |
| 键盘与焦点 | 歌曲行、搜索音源标签和菜单自行处理空格或方向键；全局播放快捷键未统一避让这些事件 | 明确快捷键作用范围，覆盖按钮、菜单、列表、弹层的焦点和 Escape 行为 |
| 搜索反馈 | 请求失败通过临时提示显示，结果区仍可能保留旧结果或显示“没有找到相关结果” | 区分输入前、加载、无结果、请求失败，保留上下文并提供重试 |
| 视觉结构 | 已有主题变量、玻璃背景、渐变、频谱与动效；页面及播放区域分别配置尺寸和留白 | 统一字体、间距、信息层次、控件状态和窗口适配，再调整装饰与动效强度 |

## 建议实施顺序

当前已实现可保存、可轮换的视觉场景，主界面轻量、沉浸界面完整；支持本地图片、渐变和专辑封面。普通集显笔记本 8GB、60Hz 仍是待实机验证的基础档；开发机结果不替代该档验收。

1. **场景交互与性能基线**：确定场景轮换、编辑和质量调整规则，形成页面方案，验证候选效果库与当前绘制基础。
2. **视觉场景与播放主流程**：实现背景素材、场景保存、效果选择与轮换；统一播放栏、歌曲列表、队列的操作与反馈，确保背景变化下仍可读、可操作。
3. **效果库与页面打磨**：扩充具有明显差异的粒子效果，完善首页、搜索和沉浸界面的层次、焦点、歌词阅读与窗口适配。涉及暂停任务的会话或数据模型变更另行安排。

每轮先明确用户操作和界面状态，形成可查看的页面方案，再实现与验证。

## 体验验收

- 按应用当前的默认窗口 1200×800 和最小窗口 900×600 检查布局、滚动、长标题与控件可达性。
- 覆盖深色与浅色主题、鼠标与键盘操作。
- 检查未登录、空队列、播放中、暂停、加载、缓冲和失败恢复。
- 明确单击、双击、右键、Enter、空格和方向键的行为，避免一次操作同时触发多个播放动作。
- 弹层打开、关闭后焦点位置明确，隐藏内容不会抢走键盘操作。
- 验证减少动态效果设置、歌词可读性和状态反馈，保留现有播放与推荐回归测试。
